# Configuration

## Module option

| Key | Type | Default | Description |
| --- | --- | --- | --- |
| `backendUrl` | `string` | `http://localhost:5010` | Origin the sidecar calls the DMS backend on (its pages registry, logs and Builder client). Set it to `${@api.API_LOCAL_BASE_URL}`. |

Everything else (agent, thinking, approvals, scope, skills, history) is set on the [Settings](/docs/modules/ai/usage/settings) page and saved as you change it.

## Environment variables

| Variable | Effect |
| --- | --- |
| `DMS_AI=0` | Start the backend without the sidecar. |
| `NODE_ENV=production` | The backend and the sidecar refuse to run. |
| `ANTHROPIC_API_KEY` | Credentials for Claude Code, when it is not logged in. |
| `OPENAI_API_KEY` | Ignored: Codex runs on a ChatGPT sign-in (a warning is logged when it is set). |
| `DMS_AI_CODEX_ALLOW_VERSION_MISMATCH=1` | Run a Codex binary other than the pinned version (logged once). |
| `DMS_COOKIE_SECURE=false` | On the frontend server, when the dashboard is reached over plain HTTP on an address other than `localhost`. |

## Agent providers

The assistant runs on **Claude Code** (the default) or **Codex**, picked on the Settings page. Both behave the same in the chat: tool calls, permission prompts and file-change animations.

A provider that cannot run (its package missing, its sign-in gone) fails the turn with the reason in the chat. The conversation is never handed to the other provider: someone who picked one provider may have picked it precisely so their code does not reach the other. Switching provider ends the live sessions of the previous one: an open conversation loses the agent's memory, its transcript stays.

### Enable Codex

::steps
### Install the CLI at the pinned version

The `codex` CLI is an optional peer dependency (about 324 MB), never installed for you. Use the exact version `peerDependencies["@openai/codex"]` pins:

```bash [Terminal]
pnpm add @openai/codex@0.154.0
```

The sidecar checks `codex --version` at spawn and refuses a mismatch, naming both versions.

### Sign in with ChatGPT

Codex runs on your ChatGPT plan, through [Sign in with ChatGPT](https://developers.openai.com/siwc): no OpenAI API key is used. On the Settings page, press **Sign in with ChatGPT** and allow plan usage. OpenAI then sends the browser back to `http://127.0.0.1:<sidecar port>/auth/chatgpt/callback`:

- On the machine running the DMS, that is the sidecar: the sign-in completes in that tab.
- On a DMS running elsewhere (a cloud dev server, a PaaS), the address reaches your own computer and the page does not load. Copy its whole address from the address bar, then press **Paste the return address** on the Settings page and paste it. The code in it only works with the secret the sidecar kept for this attempt, once, within 10 minutes.

The sign-in is per user and machine: every DMS project on it shares it. It is stored in `~/.config/dms-ai/chatgpt-auth.json` (`$XDG_CONFIG_HOME/dms-ai`, `%APPDATA%\dms-ai` on Windows, mode `0600`), never in the project. The sidecar refreshes the hourly access token itself and hands it to Codex on demand; the 30-day refresh token rotates on each refresh. Codex usage counts toward your plan's limits, which ChatGPT lets you cap per app; once reached, turns fail with OpenAI's message rather than switching to paid API usage.

**Sign out** on the same page revokes the session. To remove dms-ai from your account entirely, disconnect it in ChatGPT's settings.

### Restart the sidecar and pick Codex

Restart from the Overview, then pick **Codex** on the Settings page.
::

## Safe mode, under the hood

Safe mode lets the agent change the project only through the Builder tools, whatever the approval mode:

- On Claude, a `PreToolUse` hook refuses `Write`, `Edit`, `MultiEdit`, `NotebookEdit` and `Bash`. Reading, listing and searching stay available through `Read`, `Glob` and `Grep`, allowed inside the workspace and asked outside it.
- On Codex, the sandbox stays read-only, without network, and every escalation is declined.
- Safe mode caps **Full auto** at **Accept edits**, so the prompts that remain (reads outside the workspace, web access) still reach you.

Switching between Safe and Code mode applies from the next tool call on Claude and from the next turn on Codex, without discarding the conversation.

## Remote access

The sidecar only listens on `127.0.0.1`. The browser reaches it through the DMS frontend server (`GET /ai/channel/events` for the event stream, `POST /ai/channel/:connectionId/messages` for client messages), so the assistant works wherever the dashboard does, and the sidecar's port and credential stay on the server.

The module declares `/ai/**` as a backend prefix of the frontend server (`backendProxies`, with the signed-in member's session): the views, the blocks and the chat call its routes on the dashboard's own origin, and the frontend server forwards them to the backend. This needs a DMS frontend that supports `backendProxies`.

::note
Browsers keep at most six HTTP/1.1 connections per origin. Each dashboard tab already holds two; the assistant adds one only in the visible tab whose panel is open. Over HTTPS with HTTP/2, the limit goes away.
::
