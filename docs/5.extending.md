## Ship skills with your module

The assistant loads the skills that `antelopeJs.skills` declares in every loaded module, in the dependencies of those modules, and in the project's own dependencies, devDependencies included.

### The skill file

Each skill is a folder under a declared skills directory, with a `SKILL.md` inside:

```md [skills/my-module/SKILL.md]
---
name: my-module
description: Explains when and how to use my-module. Use when the user mentions invoices, billing pages, or the InvoiceService.
icon: i-lucide-receipt
category: billing
tags: [invoices, billing, pages]
---

# my-module

When to use it, its key APIs and pages, and its gotchas. Link to the docs for the rest.
```

The catalog reads five frontmatter fields:

| Field | Required | Value |
| --- | --- | --- |
| `name` | Yes | The skill's name. The agent sees it as `<module>:<name>`. |
| `description` | Yes | What makes the agent pick the skill. Name the cases that should trigger it. |
| `icon` | No | The icon of the skill's card. |
| `category` | No | The category of the skill's card. |
| `tags` | No | An inline list, such as `[invoices, billing]`. |

The catalog skips a `SKILL.md` that has no frontmatter, no `name` or no `description`.

### The declaration

`antelopeJs.skills` in `package.json` lists the skills directories, relative to the package. The package must also publish them in `files`:

```json [package.json]
{
  "files": ["dist", "skills"],
  "antelopeJs": {
    "skills": ["./skills"]
  }
}
```

### When the skills load

The module collects the declared directories when the backend starts and passes them to the sidecar. A new or changed skill appears after a backend restart, on the [Skills](/docs/modules/ai/usage/skills) page and in the agent.

::tip
The same declaration lets the `antelopejs` plugin from [AntelopeJS/agent-skills](https://github.com/AntelopeJS/agent-skills) sync your skills into a project's `.claude/skills/` for Claude Code, or `.agents/skills/` for Codex, outside the dashboard.
::

## The builder integration

When `@antelopejs/dms-builder` is loaded at backend start, the sidecar exposes the [Builder](/docs/modules/builder/extending) operations as `builder_*` tools, such as `builder_catalog`, `builder_add_block` and `builder_create_page`. New chats then start in Safe mode, unless the **Scope** setting makes Code mode the default. Without the Builder, the tools are absent and every chat runs in Code mode.

This package ships three skills that use the Builder tools:

| Skill | When the agent uses it |
| --- | --- |
| `dms-builder-safe` | Safe mode. The agent changes pages only through the `builder_*` tools. |
| `dms-ai-code-mode` | Code mode. The agent edits a page's code while the user watches the page. |
| `dms-external-database` | Pages over an existing database, through `builder_analyse_database`, `builder_mapping` and the `database_*` tools. |

`dms-builder-safe` and `dms-ai-code-mode` defer to the core `dms-best-practices` skill for what a page is made of.

## Owner-only routes

Every route below requires an owner. A route that relays to the sidecar answers `503 { message }` while the sidecar is down. The metrics routes answer empty figures instead, and the banner routes answer 204.

| Route | Purpose |
| --- | --- |
| `GET /ai/status`, `POST /ai/sidecar/restart` | The live status (`offline` when the sidecar does not answer), and a restart |
| `GET /ai/status/facts`, `/ai/status/banner` | The Overview's status rows and banner (204 when all is well) |
| `GET /ai/sidecar-info` | Whether the sidecar runs, has given up or is disabled. Each call starts the sidecar again if it stopped. |
| `GET /ai/metrics/kpi/:metric`, `series`, `allowed`, `top-tools`, `usage`, `usage/summary` | The figures of the Overview and of Settings |
| `GET /ai/activity`, `/ai/activity/:id`, `/ai/activity/export.csv` | The audit log, one call, and the CSV export. `from` and `to` set the period. |
| `GET /ai/changes`, `/ai/recent-changes`, `/ai/changes/:id`, `/ai/changes/:id/undo-preview`, `/ai/changes/:id/undo-confirm` | Change sets, the latest ones for the Overview, a diff, what Undo restores, and the Undo dialog |
| `POST /ai/changes/:id/undo`, `/ai/changes/:id/redo` | Undo (`{ includeLater? }`) and Redo |
| `GET /ai/skills/catalog`, `/ai/skills/conflicts` | The skills, and the duplicate-name banner |
| `GET /ai/settings`, `PUT /ai/settings` | The settings form. `PUT` takes the one field an instant save sends. |
| `GET /ai/codex/account/banner`, `POST /ai/codex/callback`, `POST /ai/codex/logout` | The ChatGPT account banner of Settings, the pasted return address of a remote sign-in, and the sign-out |
| `GET /ai/channel/events`, `POST /ai/channel/:connectionId/messages` | The chat's event stream and the client's messages |

The sidecar calls `/ai/logs`, `/ai/pages-registry`, `/ai/builder/*` and `/ai/database/*` with its own token in the `x-dms-ai-token` header. They refuse any other caller. `GET /ai/health` needs no sign-in.

## Roles

The Assistant pages are built from DMS blocks. A custom component is used only where no block draws the screen. Every page, block and child carries `$dms_ai.*` metadata, so the role editor lists them with translated names.

## Frontend

The chat panel, `DmsAiChatPanel`, is registered as a docked side panel of the dashboard with `registerSidePanel`, and renders once for the whole app. The command palette's assistant mode answers with `DmsAiPaletteAnswer`, registered with `registerCommandPaletteAssistant`.

### Start a conversation from your module

Another module's layer can open the assistant on a new conversation without depending on `dms-ai`. The plugin provides its actions under a global key. Inject them with a `null` default:

```ts
import { inject } from "vue";

interface AssistantActions {
  readonly isAvailable: boolean;
  startConversation(prompt: string, options?: { mode?: "plan" | "normal" }): void;
}

const assistant = inject<AssistantActions | null>(Symbol.for("dms-ai:assistant-actions"), null);
```

- `null` means that `dms-ai` is not installed, or that the project does not run in development. Offer nothing.
- `isAvailable` is reactive. It is `false` until the assistant runs in this tab, and stays `false` for a guest or with the sidecar disabled. Show a button only while it is `true`.
- `startConversation(prompt)` opens the panel on a new conversation with `prompt` in the composer. It sends nothing. The person reads the prompt and presses **Send**.
- `{ mode: "plan" }` sets the conversation to plan mode first. The agent then ends its turn with a plan, which the person approves with **Run with Ask first**.
