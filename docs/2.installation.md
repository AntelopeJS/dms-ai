::steps
### Add the module

```bash [Terminal]
ajs project modules add @antelopejs/dms-ai
```

The module ships its sidecar and depends on the Claude Code agent, so both install with it. It starts the sidecar with the project as its working directory.

The README compatibility table lists the supported `@antelopejs/interface-dms` range. The `@antelopejs/dms-frontend` renderer must be in the range that `engines["@antelopejs/dms-frontend"]` of `frontend-vue/package.json` declares.

### Point the sidecar at the backend

Reference the origin that the `api` module reserved, so you do not repeat a port:

```ts fragment [antelope.config.ts]
"dms-ai": {
  source: { type: "package", package: "@antelopejs/dms-ai" },
  config: {
    backendUrl: "${@api.API_LOCAL_BASE_URL}",
  },
},
```

### Add `@antelopejs/dms-builder` (recommended)

```bash [Terminal]
ajs project modules add @antelopejs/dms-builder
```

With the [Builder](/docs/modules/builder/introduction) loaded, Safe mode is available, and it is the default scope. In Safe mode the agent makes typechecked page, table and query edits, without raw file writes.

### Sign the agent in

Claude Code runs on this machine with its own credentials, either its login or `ANTHROPIC_API_KEY` in the backend's environment. To use Codex instead, see [Enable Codex](/docs/modules/ai/configuration#enable-codex).

### Start development mode and open the chat

From your project directory, run the backend with `ajs project dev` and the frontend with `ajs dms dev`, in separate terminals. Sign in as an owner. Then press `Ctrl` `Shift` `K` (`⌘` `⇧` `K` on macOS), or click the sparkle icon in the header. Pick **Builder** or **Analyst** for the conversation.

### Let other users chat

Grant the **Use the AI assistant** permission (`ai.assistant`) to a role in the workspace roles editor (`/settings/workspace/roles`). Users who hold that role get the chat in Analyst mode, which reads data only as they see it. Owners hold the permission already.

### In production

A built project (`ajs project build`, then `ajs project start`) starts the assistant in production. The chat is there for every user allowed to chat, in Analyst mode only, and the sidecar refuses Builder. Analyst runs on the agent picked in Settings, Claude Code by default or Codex, with the machine's own credentials. Sign that agent in on the production machine: for Claude Code, its login or `ANTHROPIC_API_KEY` in the backend's environment. The runtime's development flag tells development and production apart (`ajs project dev` versus a built project), not `NODE_ENV`.
::

## Stop or skip the sidecar

- To run the backend without the sidecar, set `DMS_AI=0` before you start it. The assistant is then off for everyone, in development and in production.
- To stop the sidecar, stop the project. `Ctrl` `C` reaches the sidecar through the terminal's process group. On Linux, the AntelopeJS core also terminates it on shutdown.
- A hot reload of the module keeps the sidecar running, unless the sidecar's build changed.
- If a backend crashed and left its sidecar running, the next run stops that sidecar when it starts. A sidecar also exits after 15 idle minutes. The next dashboard probe starts it again.
